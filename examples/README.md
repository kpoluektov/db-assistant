# Демо-схема `demo` — авиарейсы и посадки

Тестовая PostgreSQL-схема для проверки db-assistant. Содержит упрощённую модель авиаперевозок: аэропорты, рейсы, расписание по датам и список пассажиров на борту.

## Содержимое каталога

| Файл | Назначение |
|------|------------|
| `01_schema.sql` | DDL: создаёт схему `demo` и шесть таблиц со всеми PK/FK/индексами |
| `02_data.sql` | Идемпотентная (TRUNCATE … CASCADE) загрузка тестовых данных |

## Структура схемы

```
airports ──┬─ flights ──┬─ planned_flights ──┐
           │            │                     ├─ boardings
plane_types ──── planned_flights ─────────────┘
statuses    ──── planned_flights
```

| Таблица | Что хранит | Объём после `02_data.sql` |
|---------|------------|---------------------------|
| `airports` | Справочник аэропортов (IATA-код, город, страна, активен ли) | 10 |
| `plane_types` | Типы воздушных судов (код + описание) | 6 |
| `statuses` | Статусы рейса (`SCHEDULED`, `BOARDING`, `DEPARTED`, `DELAYED`, `ARRIVED`, `CANCELLED`) | 6 |
| `flights` | Маршруты: пара аэропортов и плановое время вылета | 12 |
| `planned_flights` | Конкретные рейсы по датам: время посадки/вылета/задержки, статус, борт | ~372 (12 × 31 день) |
| `boardings` | Посадочные талоны: пассажир, бронь, место | ~38 000 |

Период данных: **2026-07-01 … 2026-07-31**. Статус и тип борта в `planned_flights` детерминированно псевдослучайны — повторный запуск даёт ту же выборку.

## Создание базы и загрузка данных

### 1. Создать базу и пользователя в PostgreSQL

```bash
createdb dbassistant_demo
# при необходимости — отдельный пользователь:
psql -d dbassistant_demo -c "CREATE USER demo_user WITH PASSWORD 'demo_pass';"
psql -d dbassistant_demo -c "GRANT ALL PRIVILEGES ON DATABASE dbassistant_demo TO demo_user;"
```

### 2. Прогнать SQL-скрипты

```bash
psql -d dbassistant_demo -f examples/01_schema.sql
psql -d dbassistant_demo -f examples/02_data.sql
```

`02_data.sql` в конце выводит таблицу с количеством строк по каждой таблице — используйте её как sanity check.

### 3. Прописать подключение в `.env`

```
MDATA_HOST=<хост postgres>
MDATA_PORT=5432
MDATA_USER=demo_user
MDATA_PASS=demo_pass
MDATA_TYPE=postgresql
MDATA_BASE=dbassistant_demo
```

И в `.env.agent` указать схему по умолчанию:

```
YANDEX__METADATA_SCHEMA=demo
```

После этого `docker-compose up -d` — UI откроется на `http://localhost:8083/`.

## Сценарий демо
по сути это рассказ про 
    - Агент ничего не знает о БД до старта. 
    - На старте он обращается к MCP и вычитывает описание объектов хранения и их связей для всей схемы, указанной в настройке. 
    - это описание далее добавляется к системному промту агентов-делегатов для всех запросов. Это помогает агенту понимать и трансформировать вопросы пользователя, поставленные с использованием бизнес терминов, в обращение к инструментам MCP.
    - при этом агент поддерживает историю диалога (глубина задается настройкой)

и работа с тестовыми вопросами. примеры предложены ниже

## Примеры тестовых вопросов

Подобраны так, чтобы покрыть разные сценарии работы агента: от простых выборок до анализа метаданных и многотабличных JOIN.

### Простые выборки данных

- Сколько всего аэропортов в базе и сколько из них активных?
- Покажи все рейсы из Москвы (SVO и DME).
- Какие типы самолётов используются и сколько раз каждый из них был назначен на рейс?
- Сколько рейсов было запланировано на 15 июля 2026?
- Сколько рейсов в каждом статусе за весь период?

### Агрегация и аналитика

- Какой рейс перевёз больше всего пассажиров за июль 2026?
- Сколько пассажиров в среднем летает на рейсах из SVO в LED?
- Топ-5 аэропортов назначения по числу пассажиров.
- В какие дни июля было больше всего отменённых рейсов?
- Какой процент рейсов в июле был задержан (статус `DELAYED`)?

### Многотабличные JOIN

- Покажи все посадки на рейс SU0001 за 10 июля 2026 с местами и фамилиями пассажиров.
- Какой тип самолёта чаще всего летает по маршруту Москва — Санкт-Петербург?
- Найди пассажиров, которые летели на рейсах со статусом `DELAYED`.
- Сколько уникальных пассажиров (по `id_num`) посетило Сочи (AER) в июле?

### Метаданные и схема

- Какие таблицы есть в схеме `demo` и как они связаны?
- Покажи внешние ключи таблицы `boardings`.
- Какие индексы построены на таблице `planned_flights` и зачем они нужны?
- Опиши тип данных каждой колонки в `flights`.
- Покажи параметры базы данных (work_mem, shared_buffers).

### Оптимизация и проверка качества данных

- Есть ли в `boardings` дубликаты по `(flight, flight_date, place)`?
- Найди рейсы из неактивных аэропортов — их быть не должно.
- Какие места (`place`) встречаются на рейсе SU0010 чаще всего?
- Предложи индекс, который ускорит поиск посадок по номеру брони.
